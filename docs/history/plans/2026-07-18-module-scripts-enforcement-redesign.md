# Policy Module — Scripts + Enforcement Redesign — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the policy-module editor's Scripts area so scripts are a first-class named list (name + language + origin), edited in a pop-out code editor, and wired to actions on a new Enforcement tab that replaces the Parameters tab, with default/reset support and minimal-injection security.

**Architecture:** Separate *definition* (Scripts: named list) from *wiring* (Enforcement: action -> command|script). New migration reshapes `policy_module_scripts` (phase -> name/language/origin) and adds `policy_module_actions`. Service layer gains script/action CRUD + seed/restore/full-reset + `ReferencedParams`. UI: Scripts tab as INV-L list, standalone full-window editor (reused `PlurisCodeEditor` + relocated param tree), Enforcement tab with a shared `data-pluris-suggest` autocomplete widget.

**Tech Stack:** Go, Echo v4, Templ, sqlc, SQLite (modernc), vanilla JS (`PlurisCodeEditor` / CodeMirror 6), no new deps.

**Spec:** `docs/history/specs/2026-07-18-module-scripts-enforcement-redesign-design.md`

- [ ] **Step 2:** Write `012_module_scripts_actions.sql` using the rename+create+copy-forward pattern from 008 (SQLite can't drop columns cleanly). ASCII-only comments. Reshape:
  - Rename `policy_module_scripts` -> `_pre012`; create new `policy_module_scripts(id INTEGER PK, version_id INTEGER NOT NULL REFERENCES policy_module_versions(id) ON DELETE CASCADE, name TEXT NOT NULL, language TEXT NOT NULL DEFAULT 'sh' CHECK(language IN ('sh','powershell','python')), source TEXT NOT NULL DEFAULT '', origin TEXT NOT NULL DEFAULT 'custom' CHECK(origin IN ('default','custom')), seq INTEGER NOT NULL DEFAULT 0, UNIQUE(version_id, name))`.
  - Copy-forward: each `_pre012` row becomes a named script `name = phase`, `language = 'sh'` (or `'python'` for validate/report to keep them scripted), `source = source`, `origin='custom'`, preserving `version_id`/`seq`. Drop `_pre012`.
  - Create `policy_module_actions(id INTEGER PK, version_id INTEGER NOT NULL REFERENCES policy_module_versions(id) ON DELETE CASCADE, action_key TEXT NOT NULL, label TEXT NOT NULL DEFAULT '', kind TEXT NOT NULL DEFAULT 'script' CHECK(kind IN ('command','script')), value TEXT NOT NULL DEFAULT '', origin TEXT NOT NULL DEFAULT 'custom' CHECK(origin IN ('default','custom')), seq INTEGER NOT NULL DEFAULT 0, UNIQUE(version_id, action_key))`.
  - For every existing version, seed one action row per carried-forward script: `action_key = <phase name>`, `kind='script'`, `value=<script name>`, `origin='custom'` (so no behaviour is lost). Index both tables by `version_id`.
- [ ] **Step 3:** Run `sqlc generate` (after 1.2's query edits — order: edit schema+queries, then one `sqlc generate`). For this task alone, confirm the migration parses by building: `go build -buildvcs=false ./pkg/database/...`.
